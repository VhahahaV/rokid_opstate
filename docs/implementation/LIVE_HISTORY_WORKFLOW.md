# 历史回放、实时观察与眼镜演示

本入口按“公共历史 → 实时观察 → 主动服务”组织，手机直接使用已保存的模型 API Key。服务器连接不是前置条件。

## 操作流程

1. 在眼镜打开 OPSTATE。应用自动准备相机与通信；首次使用会请求相机权限。手机连接后须显示“设备就绪”。
2. 手机“开始现场验证”打开准备页。默认选择 **R6 历史续接**：拖动 266 个锚点的进度、上一/下一锚点，或播放/暂停历史预览。页面显示原始日期和最近公共文字。
3. 点“载入历史并连接眼镜”。只载入选定锚点以前可见的历史，眼镜显示“历史已就绪”；这一步不调用模型，也不拍照。
4. 点“开始实时服务”。60 秒基线采样启用；新情境等事件可触发额外采样。采集、传输或模型仍忙时，采样会顺延，不并行拍照。
5. “实时观察与情境”可关闭/开启自动拍照、手动“拍照观察一次”，并查看最近真实照片与质量提示。
6. “添加合成情境”选择 Email、Calendar、消息或备忘，填写标题和内容。可以更新当前任务，也可以建立新任务；选择同时显示时，眼镜收到独立情境卡。暂停期间加入的最近一张情境卡在继续时显示，完整文字始终保存在历史中。
7. 可开启/关闭“眼镜演示视图”。演示视图展示阶段、当前情境、观察与真实回执计数；确认键收起/展开详情。服务卡优先显示。安静视图无常驻状态，NO_SERVICE 不产生通知或服务卡。

准备页也保留 **情境脚本** 模式，可按 12 分钟会议情境时间线拖动，跳转上一/下一情境，暂停和继续。

## 回放与记录语义

- R6 预览不执行历史模型调用，不生成历史服务回执。原“数据”页的严格 266 锚点 HTTP mock 协议验证工具独立保留。
- 续接载入经过校验的公共观察前缀，选择锚点的任务作为初始候选。Gold、教师回执、未来观察不导入。
- 将选定历史锚点的时间对齐到会话启动时刻，保留历史记录之间的时间差。导出记录原始时间、对齐量、数据目录哈希和锚点；**正文日期不自动改写**。这是一种部署演示输入，不是原 Track A 实验复现。
- 运行中拖动情境或历史进度会先停止并保存旧片段，再使用新 session ID/epoch 从目标位置创建片段。历史记录和已提交回执不被删除或重写，旧片段的迟到结果不可进入新片段。新配置记录父片段 ID。
- 脚本暂停会冻结情境播放位置；实际拍照、观察可见时间、模型输出与回执仍使用真实时间，现实日程截止时间不会随暂停移动。
- 手工输入作为当前时刻收到的 `SYNTHETIC_CONTEXT`，保存明确的来源和类型。材料更新取消旧的进行中推理/采集，后续请求包含新内容。
- 启动提示使用独立的 `SESSION_STATUS_VISIBLE_ACK` 确认两帧绘制，不计入服务 Receipt。眼镜状态不会被当作模型的 SERVICE。
- 图像过暗/过亮/不清晰时最多自动重试一次，保留照片并说明未评估的原因。模型非法输出保留原文，不截断为一条看似成功的服务。

## 实现位置

- `SessionSetupSheet.kt`：开始页、历史预览与合成情境表单，底部固定主要操作。
- `ScenarioPlaybackPanel.kt` / `ObservationControls.kt`：进度控制、相机操作、最近图像与演示开关。
- `replay/PublicReplayDataset.kt` / `HistoryContinuation.kt`：公共数据校验、因果前缀与时间对齐；共用读取器移至 phone library。
- `StudyRuntimeEngine.kt`：单 actor 管理载入、继续、跳转、采样、模型、显示和记录。
- 眼镜 `MainActivity.kt` / `GlassesStudyService.kt`：自动准备、短提示、情境卡、演示状态与服务可见确认。
